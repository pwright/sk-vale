# skupper-fix

Reads Vale findings, traces them to Markdown sources, categorizes them, and applies fixes to the `.md` files.

## Arguments

- `--rule <name>` — Fix only findings for a specific rule (e.g., `ShortDescription`, `ContentType`)
- `--file <md-path>` — Fix only findings in a specific file (e.g., `kube-yaml/custom-certs.md`)
- `--dry-run` — Show what would be fixed without making changes
- `--skip-convert` — Use existing vale-report.json without re-running conversion

## Steps

1. **Get current findings**:

   If `--skip-convert` is set, read existing `vale-report.json`. Otherwise run conversion first:
   ```bash
   bash scripts/convert-skupper.sh --input-dir ~/repos/sk/skupper-docs/doc-input
   ```

2. **Trace findings to MD sources**:
   ```bash
   python3 -I skills/shared/scripts/traceback.py vale-report.json assembly-map.json
   ```

3. **Categorize findings**:

   For each finding, determine if it is:

   | Category | Description | Action |
   |----------|-------------|--------|
   | **Directly fixable** | Can fix in `.md` source and the fix survives conversion | Apply fix |
   | **Pipeline awareness** | Requires understanding how the conversion works | Apply with care |
   | **Conversion artifact** | Generated by the conversion process, not fixable in source | Skip, note in report |

   ### Common fixable rules and how to fix them

   | Rule | Fix in Markdown |
   |------|----------------|
   | `ShortDescription` | Add a paragraph immediately after each `#` / `##` heading — this becomes the `[role="_abstract"]` paragraph |
   | `ContentType` | The content type is inferred from heading text. Procedures use gerunds ("Creating", "Configuring"). If the heading doesn't match, rename it. |
   | `TaskContents` | Ensure procedure files have a numbered list — this becomes the `.Procedure` block |
   | `NestedSection` | Avoid headings deeper than `##` — deeper levels cause nested sections which violate DITA constraints. Restructure content or split into separate files. |
   | `AssemblyContents` | No prose between sections at the same heading level — only intro text before the first sub-section is allowed |

4. **Apply fixes**:

   For each fixable finding, locate the source `.md` file. The source files are in the skupper-docs repo:
   - Check `~/repos/sk/skupper-docs/doc-input/<md-path>`
   - Or use the `--source-dir` from the last conversion

   Apply the fix to the `.md` file using the Edit tool. Follow patterns from passing files (see AGENTS.md: "look at files that pass with zero warnings").

   If `--dry-run`, show the proposed changes without applying them.

5. **Verify fixes**:

   Re-run the conversion pipeline and check that findings are resolved:
   ```bash
   bash scripts/convert-skupper.sh --input-dir ~/repos/sk/skupper-docs/doc-input
   vale --output=JSON assemblies/ modules/
   ```

6. **Report**:
   ```
   Fixed: 8 findings in 3 files
   Skipped: 2 conversion artifacts
   Remaining: 1 finding (NestedSection requires restructuring)

   Files modified:
     ~/repos/sk/skupper-docs/doc-input/kube-yaml/custom-certs.md
     ~/repos/sk/skupper-docs/doc-input/overview/security.md
     ~/repos/sk/skupper-docs/doc-input/kube-cli/site-configuration.md
   ```

## Notes

- Always fix the `.md` source, never the generated `.adoc` files
- After fixing, re-run conversion to verify — some fixes interact with the conversion pipeline
- `NestedSection` fixes may require splitting content into multiple `.md` files and updating `mkdocs.yml`
- Study passing files before fixing: find modules with zero Vale issues and match their patterns
