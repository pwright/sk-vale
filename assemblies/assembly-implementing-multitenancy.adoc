= Implementing multitenancy with {registry}

[role="_abstract"]
You can implement multitenancy with {registry} on {kubernetes} by using the {operator}. {registry} uses a multi-instance operator pattern in which each tenant receives a dedicated `ApicurioRegistry3` custom resource (CR).

The {operator} reconciles each CR into an independent set of {kubernetes} resources. This approach provides strong isolation between tenants at the infrastructure level. It uses {kubernetes}-native mechanisms for security, resource management, and network segmentation.

NOTE: {registry} 3.x has no built-in tenant concept: the tenant ID, tenant manager, and per-tenant storage of {registry} 2.x were removed and are not planned to return. For lighter isolation inside one instance, see xref:multitenancy-lightweight-group-isolation_{context}[].

== Prerequisites


* {installing-the-registry-openshift}
* The {operator} is installed.
