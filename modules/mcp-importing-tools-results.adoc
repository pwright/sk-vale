= Import results


Each tool, and the `MCP_SERVER` artifact, has one of the following statuses:

[%header,cols="1,3"]
|===
|Status |Meaning

|`CREATED`
|A new `MCP_TOOL` artifact was created.

|`NEW_VERSION`
|The tool's definition changed, and a new version was added. For the server, a new version with different references was added.

|`UNCHANGED`
|A stored version already matches the tool's definition. For the server, the latest version already has the same references, so no version was added.

|`REJECTED`
|A rule, such as `COMPATIBILITY`, rejected the new definition, and the causes list the violations. Nothing was written for the tool, and the new server version does not reference it, because no stored version matches what the server offers. A tool is also rejected when an artifact with its ID exists and is not an `MCP_TOOL`.

|`REMOVED`
|The previous server version referenced the tool, but the server no longer lists it. The tool's artifact is not changed or deleted, and the new server version does not reference it.
|===

Each tool is published like any other version: rules, write hooks, authorization, and auditing apply to each tool. Before any tool is written, the import checks that the server lists no tool name twice and that you can write every existing tool artifact, so these failures leave nothing imported. A rule rejecting one tool does not stop the others. Tools are otherwise not imported atomically: if another error occurs partway through, tools that were already accepted stay stored. In a dry run, the report states whether a new server version would be added, but the server version is not checked against rules, because the tools it would reference do not exist yet.

The new server version references exactly the imported tools. References that you added to an earlier version by hand are not carried over.
