= Changes to JSON Schema validity checking in {registry} 3.4

[role="_abstract"]
Before version 3.4, {registry} checked JSON Schema validity by loading the schema.
If you used the `VALIDITY` rule with JSON Schema artifacts before version 3.4, the following behavior changed:

* {registry} now checks artifacts in draft 2019-09.
The earlier checker rejected them at the `FULL` level with a message that ends with `JSON schema version 2019-09 is not supported yet.`

* {registry} validates a schema against the meta-schema of its draft instead of only loading it, and rejects a schema that its draft forbids.
For example, in draft 4, `exclusiveMinimum` is a boolean that requires `minimum`, and in draft 2020-12, `$dynamicAnchor` must not be empty.

* The `context` of each rule violation is now a JSON Pointer, such as `/properties/price/minimum`, instead of the earlier location that started with `#`.
Update clients that match the earlier contexts.

* {registry} can report more than one problem at once, at most one per location.
The earlier checker reported one problem at a time.

* {registry} does not check stored versions again.
The changes apply when you add content or finalize a draft.
