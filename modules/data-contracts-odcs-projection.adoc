= ODCS projection mapping

[role="_abstract"]
When you submit an ODCS contract, {registry} parses the YAML, stores it as an `ODCS_CONTRACT` artifact, and projects its contents onto the referenced schema artifacts. Each projection is namespaced by the contract ID.

.ODCS projection mapping
[cols="2,3", options="header"]
|===
|ODCS section |Projected to

|`info.status`
|`contract.\{contractId}.status` label (case-insensitive: draft->DRAFT, active->STABLE, deprecated or retired->DEPRECATED, any other value->DRAFT)

|`info.version`
|`contract.\{contractId}.version` label

|`id`
|`contract.\{contractId}.id` label

|`info.dataClassification`
|`contract.\{contractId}.classification` label

|`team.name` / `team.domain` / `team.contact`
|`contract.\{contractId}.owner.team`, `.owner.domain`, `.support.contact` labels

|`quality.accuracy` rules
|Artifact-level CEL domain rules named `odcs:\{contractId}:\{name}` (kind `CONDITION`, mode `WRITE`)

|`quality.completeness` rules
|`contract.\{contractId}.quality.completeness.{field}` labels

|`quality.freshness.maxStaleness`
|`contract.\{contractId}.quality.freshness.maxStaleness` label

|`schemas[].fields[].pii` / `.classification` / `.tags`
|`field-tag.\{contractId}:\{fieldPath}\|\{tagName}` labels with value `EXTERNAL`, set on the version named in `location` (latest version if omitted)

|`serviceLevel.availability`, `serviceLevel.latency.p50`, `serviceLevel.latency.p99`
|`contract.\{contractId}.sla.availability`, `.sla.latency.p50`, `.sla.latency.p99` labels (stored, not enforced by registry). Other `serviceLevel` fields, such as throughput, are not projected.
|===

Other ODCS sections, such as `info.title` and descriptions, are kept only in the stored contract YAML.

A status from `info.status` that becomes `STABLE` or `DEPRECATED` also sets `contract.\{contractId}.lifecycle.stable-date` or `contract.\{contractId}.lifecycle.deprecated-date`. A field tag whose label key would be longer than 256 characters is skipped, with a warning in the response.

ODCS accuracy rule thresholds (default 1.0) determine the rule's `onFailure` action. The rule `params` contain the `source` and `threshold` values.

.Accuracy rule threshold mapping
[cols="1,1,3", options="header"]
|===
|Threshold |Failure action |Behavior

|1.0 or higher
|`ERROR`
|Rule evaluation stops at this failure.

|0.95 to below 1.0
|`DLQ`
|The violation is recorded and evaluation continues. No dead letter queue routing is implemented.

|Below 0.95
|`NONE`
|The violation is recorded and evaluation continues.
|===
