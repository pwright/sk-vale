= How references affect content identity and deletion

[role="_abstract"]
References are stored with the content, not with the artifact version, and they are part of the content's identity:

* A reference always points to an exact artifact version. It does not follow the latest version. To use a new version of a referenced artifact, create a new version of the referencing artifact.
* Both the content hash and the canonical hash include the references. The same content with different references is stored as different content, with a different content ID.
* A version in the `DISABLED` state can still be resolved as a reference.
* In the core REST API, deleting an artifact or version that other versions reference is allowed. The references remain listed, but they can no longer be resolved, so dereferencing the referencing content fails. Check the inbound references (`refType=INBOUND`) before deleting. The Confluent-compatible API refuses to delete referenced subjects and versions.
* Without an `INTEGRITY` rule, a reference can point to an artifact version that does not exist yet. Configure `INTEGRITY` with `FULL` or `REFS_EXIST` to reject such references.

For a runnable demonstration, see the link:https://github.com/Apicurio/apicurio-registry/tree/main/examples/schema-references[schema-references example].
