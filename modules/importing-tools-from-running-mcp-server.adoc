= Importing tools from a running MCP server

[role="_abstract"]
Instead of writing `MCP_TOOL` artifacts by hand, you can import the tools of a running MCP server, and import them again when the server changes. The same compatibility rules apply, so an incompatible tool change is rejected on import.

The stack includes a demo MCP server, `weather-mcp`, which only {registry} can reach. Its `/mcp` endpoint lists `get_forecast`, as registered in the demo catalog, and a new tool, `get_alerts`. Its `/mcp-v2` endpoint plays the same server after a breaking change: `get_forecast` now requires a `units` property.

.Procedure
. Import the tools of the running server into the `weather` MCP server artifact:
+
[source,bash]
----
curl -X POST http://localhost:8080/apis/registry/v3/groups/demo/artifacts/weather/mcp-import \
  -H "Content-Type: application/json" \
  -d '{"url": "http://weather-mcp:8000/mcp"}'
----
+
The report lists each tool. `get_alerts` is `CREATED` as the `weather.get_alerts` artifact. `get_forecast` is `UNCHANGED`, because version `1` already has the same definition. The `weather` server artifact gets version `2`, which references both tools.

. Check what a redeployed server with a breaking change would do, without writing anything:
+
[source,bash]
----
curl -X POST http://localhost:8080/apis/registry/v3/groups/demo/artifacts/weather/mcp-import \
  -H "Content-Type: application/json" \
  -d '{"url": "http://weather-mcp:8000/mcp-v2", "dryRun": true}'
----
+
`get_forecast` is `REJECTED` by the `BACKWARD` compatibility rule, and its causes include `A property was made 'required'.` Callers that send only `city` would break.

. Import again from the unchanged server:
+
[source,bash]
----
curl -X POST http://localhost:8080/apis/registry/v3/groups/demo/artifacts/weather/mcp-import \
  -H "Content-Type: application/json" \
  -d '{"url": "http://weather-mcp:8000/mcp"}'
----

.Verification
* The report's `status` and every tool's `status` are `UNCHANGED`: importing again from the same server writes nothing.

The stack allows imports only from `weather-mcp`, over plain HTTP, because it runs on the stack's private network. For the settings, the import results, importing in the background with `"async": true` for servers with many tools, and the outbound connection rules, see xref:getting-started/assembly-mcp-tool-features.adoc[MCP tool definition features].

NOTE: Importing tools from a running MCP server is available from {registry} 3.4.
