= Overview

[role="_abstract"]
The Data Contracts framework enables teams to define, enforce, and track formal agreements about schema structure, ownership, and quality using the industry-standard ODCS format.

A data contract in {registry} combines the following elements:

ODCS format:: Contracts are submitted as ODCS v3.1 YAML documents and projected onto schema artifacts.
Metadata:: Ownership, classification, SLA, and support information are projected as labels.
Lifecycle:: Status tracking (DRAFT, STABLE, DEPRECATED) and promotion stages (DEV, STAGE, PROD).
Quality rules:: Accuracy and completeness rules from ODCS are projected as CEL contract rules.
Field tags:: PII and classification annotations are stored as version labels, with automatic extraction from Avro, JSON Schema, and Protobuf schemas.
Multi-contract support:: Multiple contracts can reference the same schema artifact without overwriting each other.

NOTE: Data contracts are always available. No special configuration is required: submitting a contract is an explicit opt-in action.
