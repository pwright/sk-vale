= Exporting and importing registry data using {registry} REST API commands

[role="_abstract"]
As an administrator, you can use the Core Registry API v3 to export data from one {registry} instance and import into another {registry} instance, so you can migrate data between different instances.

The export operation creates a ZIP archive containing registry data and metadata.
By default, it includes all groups and global rules.
You can limit the export to a single group by specifying the `groupId` query parameter.

.Prerequisites

* {registry} is installed and running in your environment.
* {registry} instances have been created:
** The source instance that you want to export data from contains at least one schema or API artifact.
** The target instance that you want to import data into is empty to preserve unique IDs.

.Procedure
. Export the {registry} data from your existing source {registry} instance:
+
[source,bash]
----
$ curl MY-REGISTRY-URL/apis/registry/v3/admin/export \
  -H "Authorization: Bearer $ACCESS_TOKEN" \
  --output my-registry-data.zip
----
+
`MY-REGISTRY-URL` is the
hostname on which the source {registry} is deployed. For example: `\http://my-source-registry:8080`.
+
To export only one group, add the `groupId` query parameter instead:
+
[source,bash]
----
$ curl --fail-with-body --get MY-REGISTRY-URL/apis/registry/v3/admin/export \
  -H "Authorization: Bearer $ACCESS_TOKEN" \
  --data-urlencode "groupId=my-group" \
  --output my-group-data.zip
----
+
A group export excludes global rules and artifacts in other groups.
If the group's artifacts reference artifacts in another group, include those dependencies in your migration plan.
The specified group must exist.

. Import the registry data into your target {registry} instance:
+
[source,bash]
----
$ curl -X POST "MY-REGISTRY-URL/apis/registry/v3/admin/import" \
  -H "Content-Type: application/zip" -H "Authorization: Bearer $ACCESS_TOKEN" \
  --data-binary @my-registry-data.zip
----
+
`MY-REGISTRY-URL` is the
hostname on which the target {registry} is deployed. For example: `\http://my-target-registry:8080`.
+
When importing a group export, use the file name `my-group-data.zip` instead.
By default, the target registry must be empty, and the import preserves global IDs and content IDs.
To import into a nonempty registry, set `requireEmptyRegistry=false` and set both `X-Registry-Preserve-GlobalId` and `X-Registry-Preserve-ContentId` headers to `false` to generate IDs on the target.
These options do not resolve conflicts between existing artifact coordinates.

.Verification
* Retrieve the imported artifacts and versions from the target registry and compare their content with the source.
Check the server log for failed or skipped entities because an import can skip an individual entity without failing the entire request.
