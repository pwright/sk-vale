= MCP HTTP mode without token forwarding

[role="_abstract"]
By default, HTTP mode forwards each caller's bearer token to {registry}, so role-based access control applies per user. You can disable token forwarding so that all callers act as one shared service account, for example, in shared deployments where OIDC only controls access to the MCP endpoint.

To disable token forwarding, set `apicurio.mcp.http.forward-token=false`. Callers still authenticate to the MCP server with OIDC, by using the same Keycloak realm and HTTP authentication settings as with token forwarding enabled. MCP tool calls then use the shared `apicurio.mcp.auth.*` service account against {registry}, not the caller's token.

Disabled token forwarding requires the following configuration:

* `apicurio.mcp.http.enabled=true`, together with the Quarkus MCP HTTP and OIDC settings that HTTP transport requires
* `apicurio.mcp.http.forward-token=false`
* `apicurio.mcp.auth.*` client credentials (token endpoint, client ID, and client secret), the same as in stdio mode when {registry} is secured
