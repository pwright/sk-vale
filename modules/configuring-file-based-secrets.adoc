= Loading configuration values from files

[role="_abstract"]
You can load a {registry} configuration value from a file, such as a mounted secret, to keep the value out of the deployment's environment variables.

.Prerequisites
* You can update and restart the {registry} deployment.
* The file contains the required configuration value and is readable by the {registry} process.

.Procedure
. Mount the file in the {registry} container, for example, at `/run/secrets/db_password`.
Use file permissions that restrict access to the processes that need the value.
. Set the environment variable for the configuration property with an additional `_FILE` suffix:
+
[source,properties]
----
APICURIO_DATASOURCE_PASSWORD_FILE=/run/secrets/db_password
----
+
Alternatively, configure the property with a `.file` suffix in the server configuration:
+
[source,properties]
----
apicurio.datasource.password.file=/run/secrets/db_password
----
+
The file value takes precedence over a directly configured value for `apicurio.datasource.password`.
{registry} removes leading and trailing whitespace from the file contents.
This mechanism applies to configuration properties resolved by the server, including properties other than passwords.
. Restart the deployment to load the value.
+
{registry} caches the value after reading the file.
Restart the deployment after changing the file or its configured path.

.Verification
* Check the server log for a message that confirms the file was loaded for `apicurio.datasource.password`.
The message identifies the property without displaying the secret value.

.Troubleshooting
* If the server reports that the file is missing or unreadable, check the mounted path and file permissions.
A configured file that cannot be read causes configuration resolution to fail; the server does not fall back to the directly configured value.
