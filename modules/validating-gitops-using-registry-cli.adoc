= Validating a Git revision using the CLI

[role="_abstract"]
You can validate the content of a Git revision before merging a change. Validation does not change the live registry content.

.Prerequisites
* Your CLI context points to a {registry} instance that uses GitOps storage.
* The server has `apicurio.gitops.validate.enabled=true`.
* The repository ID is configured on the server, and the server can fetch the Git revision.
* You have administrator access when authorization is enabled.

.Procedure
. Submit a branch, tag, or pull request ref for validation:
+
[source,bash]
----
$ acr gitops validate --repo primary --ref refs/heads/proposed-schemas --timeout 300
----
+
Replace `primary` with the configured repository ID. The CLI waits for the validation task to finish and displays its result, resource counts, and errors. The default timeout is 300 seconds.
. Optional: Use JSON output to process the validation result in a pipeline:
+
[source,bash]
----
$ acr gitops validate --repo primary --ref refs/heads/proposed-schemas --output-type json
----
+
JSON output includes the task ID, task state, validation result, timestamps, counts, and error details. A failed task, failed validation result, or timeout returns exit code `1`.
. Optional: Retain the server task for later inspection:
+
[source,bash]
----
$ acr gitops validate --repo primary --ref refs/heads/proposed-schemas --no-cleanup
----
+
By default, the CLI attempts to delete the task when it finishes waiting, including after an error or timeout. With `--no-cleanup`, the task remains available until it expires or you delete it through the REST API.

.Verification
* Check the command exit code and the reported validation result. Successful validation reports `success`.
