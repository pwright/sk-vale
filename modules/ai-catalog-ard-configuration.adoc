= AI Catalog and ARD configuration properties

[role="_abstract"]
AI Catalog publishing and ARD search are disabled by default.
You can enable each feature independently with its configuration property.

TIP: To enable all the agent registry discovery features at once (A2A, MCP tools, the MCP Registry API, the AI Catalog, ARD, and the web console's *Agents* tab), set `apicurio.features.experimental.enabled=true` and `apicurio.agents.enabled=true`. A feature's own property, such as `apicurio.a2a.enabled`, still takes precedence, so you can turn a single feature off. Features that connect to other servers, such as importing tools from MCP servers, are not included and must be enabled separately.

.AI Catalog and ARD configuration properties
[cols="2,1,3",options="header"]
|===
|Property |Default |Description

|`apicurio.ai-catalog.enabled`
|Value of `apicurio.agents.enabled`, `false` by default
|Whether to enable the `/.well-known/ai-catalog.json` and `/.well-known/ard.json` endpoints

|`apicurio.ai-catalog.publisher-domain`
|_Derived from request host_
|The `<publisher>` segment in `urn:air:` identifiers.
If you do not configure this property, {registry} uses the `X-Forwarded-Host` header if present, otherwise the request host and port.

|`apicurio.instance.name`
|`Apicurio Registry`
|Display name for this registry instance, reported as the catalog's `host.displayName`

|`apicurio.ai-catalog.host-name`
|_Not set_
|Deprecated since 3.4.0. Use `apicurio.instance.name`, which takes precedence when both are set.

|`apicurio.ard.enabled`
|Value of `apicurio.agents.enabled`, `false` by default
|Whether to enable the `POST /ard/search`, `GET /ard/agents`, and `POST /ard/explore` endpoints
|===

The catalog document reports AI Catalog specification version `1.0`, the version {registry} implements. The properties `apicurio.ai-catalog.spec-version` and `apicurio.ard.federation.default` are deprecated since 3.4.0 and have no effect.
