= Trying content search with Docker Compose

[role="_abstract"]
You can run {registry} and Elasticsearch locally to evaluate content search before you configure an existing deployment.

.Prerequisites
* You have installed Docker and Docker Compose.
* You have selected a {registry} container image version.

.Procedure
. Create a `compose.yaml` file with the following content:
+
[source,yaml]
----
services:
  elasticsearch:
    image: docker.elastic.co/elasticsearch/elasticsearch:9.2.3
    environment:
      discovery.type: single-node
      xpack.security.enabled: "false"
      ES_JAVA_OPTS: "-Xms512m -Xmx512m"
    healthcheck:
      test: ["CMD-SHELL", "curl -sf http://localhost:9200/_cluster/health || exit 1"]
      interval: 10s
      timeout: 5s
      retries: 10
  registry:
    image: apicurio/apicurio-registry:VERSION
    environment:
      APICURIO_FEATURES_EXPERIMENTAL_ENABLED: "true"
      APICURIO_SEARCH_INDEX_ENABLED: "true"
      QUARKUS_ELASTICSEARCH_HOSTS: "elasticsearch:9200"
      APICURIO_SEARCH_INDEX_ELASTICSEARCH_NUMBER_OF_REPLICAS: "0"
    ports:
      - "127.0.0.1:8080:8080"
    depends_on:
      elasticsearch:
        condition: service_healthy
----
+
Replace `VERSION` with the container image version. The {registry} 3.4 build includes the Elasticsearch 9.2.3 Java client and supports Elasticsearch 9.x servers; use a server version that is the same as or newer than the client within the 9.x series. For another {registry} release, select an Elasticsearch version compatible with its Java client. This local example uses in-memory registry storage and disables Elasticsearch authentication. It is intended for evaluation; it does not preserve registry data when you recreate the container.
. Start the services:
+
[source,bash]
----
docker compose up -d
----
. Check the application logs:
+
[source,bash]
----
docker compose logs registry
----

.Verification
* Register an artifact with the REST API, then search for a word in its content at `http://localhost:8080/apis/registry/v3/search/versions`.
