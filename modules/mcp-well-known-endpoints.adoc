= Well-known endpoints

[role="_abstract"]
You can search for, retrieve, and compare MCP tool definitions by using the following well-known endpoints.

The `/.well-known/mcp-tools` endpoints are available only when MCP tools support is enabled, and require read-level authorization. {registry} also serves them under `/apis/registry/v3/well-known/mcp-tools`, which is where the generated SDK clients call them.

The `GET /.well-known/mcp-tools` endpoint searches for registered MCP tool definitions with filtering support. It accepts the following query parameters:

[cols="1,1,3"]
|===
|Parameter |Type |Description

|`name`
|string
|Filter by tool name (partial match)

|`parameter`
|string (repeatable)
|Filter by input parameter name

|`offset`
|integer
|Pagination offset (default: 0)

|`limit`
|integer
|Pagination limit (default: 20)
|===

.Example request
[source,bash]
----
curl "http://localhost:8080/.well-known/mcp-tools?parameter=location"
----

.Response: `McpToolSearchResults`

[source,json]
----
{
  "count": 1,
  "tools": [
    {
      "groupId": "mcp-tools",
      "artifactId": "weather-tool",
      "name": "get_weather",
      "title": "Weather Information Provider",
      "description": "Get current weather information",
      "owner": "admin",
      "createdOn": 1700000000000,
      "parameters": ["location"]
    }
  ]
}
----

The `GET /.well-known/mcp-tools/\{groupId}/\{artifactId}` endpoint retrieves a specific registered MCP tool definition. It accepts the following path parameters:

`groupId`:: The group containing the tool definition
`artifactId`:: The artifact ID of the tool definition

You can optionally specify the following query parameter:

`version` (optional):: Specific version (defaults to latest)

The response is the MCP tool definition JSON document.

The `GET /.well-known/mcp-tools/\{groupId}/\{artifactId}/compatible` endpoint returns the registered MCP tools whose `inputSchema` accepts every output that the `outputSchema` of the specified tool permits. These are the tools with the `COMPATIBLE` verdict described in <<mcp-cross-tool-compatibility_{context},Cross-tool compatibility>>. The specified tool itself is never returned, and no tools are returned when its `outputSchema` is absent or cannot be compared. The endpoint accepts the `groupId` and `artifactId` path parameters and the following query parameters:

[cols="1,1,3"]
|===
|Parameter |Type |Description

|`version`
|string
|Version of the specified tool to compare (defaults to latest)

|`offset`
|integer
|Pagination offset (default: 0)

|`limit`
|integer
|Pagination limit (default: 20)
|===

.Example request
[source,bash]
----
curl "http://localhost:8080/.well-known/mcp-tools/orders/get-order/compatible"
----

.Response: `McpCompatibleToolsResults`
[source,json]
----
{
  "count": 1,
  "tools": [
    {
      "groupId": "orders",
      "artifactId": "send-receipt",
      "owner": "",
      "createdOn": 1794940649173,
      "parameters": [
        "orderId",
        "total"
      ]
    }
  ]
}
----

The `GET /.well-known/mcp-tools/\{groupId}/\{artifactId}/compatibility` endpoint makes the same comparison and returns every compared tool with its verdict, and with the reasons and limitations that decide it. The endpoint accepts the `groupId` and `artifactId` path parameters and the following query parameters:

[cols="1,1,3"]
|===
|Parameter |Type |Description

|`version`
|string
|Version of the specified tool to compare (defaults to latest)

|`verdict`
|string (repeatable)
|Return only the tools with this verdict: `COMPATIBLE`, `INCOMPATIBLE`, or `INDETERMINATE`. Repeat the parameter to select more than one. By default, all three verdicts are returned.

|`offset`
|integer
|Pagination offset, applied after the `verdict` filter (default: 0)

|`limit`
|integer
|Pagination limit, applied after the `verdict` filter (default: 20)
|===

.Example request
[source,bash]
----
curl "http://localhost:8080/apis/registry/v3/well-known/mcp-tools/orders/get-order/compatibility?verdict=INCOMPATIBLE&verdict=INDETERMINATE"
----

.Response: `McpToolCompatibilityResults`
[source,json]
----
{
  "candidateTotal": 4,
  "evaluated": 3,
  "scanLimit": 500,
  "complete": true,
  "totals": {
    "compatible": 1,
    "incompatible": 1,
    "indeterminate": 1
  },
  "count": 2,
  "limitations": [],
  "results": [
    {
      "tool": {
        "groupId": "orders",
        "artifactId": "convert-currency",
        "owner": "",
        "createdOn": 1794940649237,
        "parameters": [
          "total",
          "currency"
        ]
      },
      "verdict": "INDETERMINATE",
      "reasons": [],
      "limitations": [
        {
          "code": "UNSUPPORTED_KEYWORD",
          "side": "CONSUMER",
          "pointer": "/inputSchema/properties/currency/enum",
          "message": "'enum' is not evaluated yet"
        }
      ]
    },
    {
      "tool": {
        "groupId": "orders",
        "artifactId": "schedule-delivery",
        "owner": "",
        "createdOn": 1794940649203,
        "parameters": [
          "orderId",
          "address"
        ]
      },
      "verdict": "INCOMPATIBLE",
      "reasons": [
        {
          "code": "REQUIRED_NOT_GUARANTEED",
          "producerPointer": "/outputSchema/required",
          "consumerPointer": "/inputSchema/required/1",

        }

----

For the fields of the response and the codes of reasons and limitations, see <<mcp-cross-tool-compatibility-reference_{context},Cross-tool compatibility reference>>.

Both endpoints page their results with `offset` and `limit`. An `offset` or `limit` sent without a value takes its default, 0 or 20. A negative `offset` is treated as 0, a negative `limit` as 1, and a `limit` above 1000 as 1000, including values outside the 32-bit integer range. An `offset` or `limit` that is not a number is rejected with a `404` error, which the conversion of the request parameters returns before the endpoint runs. An unknown `verdict` value is rejected with a `400` error. Both endpoints return a `404` error when MCP tools support is disabled, when the specified tool or version does not exist, or when the artifact is not an `MCP_TOOL`.

IMPORTANT: The `offset` and `limit` parameters of the `/.well-known/mcp-tools/\{groupId}/\{artifactId}/compatible` endpoint now follow these rules. Earlier versions of {registry} returned one tool for a `limit` of 0, where an empty page is now returned, and returned an error for an `offset` or `limit` sent without a value or outside the 32-bit integer range, or for a `limit` close to the 32-bit maximum combined with a non-zero `offset`, where the values now take their defaults or are normalized.

IMPORTANT: The `/.well-known/mcp-tools/\{groupId}/\{artifactId}/compatible` endpoint now returns a different set of tools than earlier versions of {registry}, which returned any candidate whose `inputSchema` declared every property in the `outputSchema` of the specified tool. A candidate that ignores part of the output is now returned. A candidate is no longer returned when it requires an input that the `outputSchema` does not require, when it rejects a value that the output can contain, such as `null`, or when the comparison cannot evaluate part of either schema. Structure nested inside a property is now compared as well, so a candidate whose nested types or nested required inputs do not match the output is no longer returned.

The `GET /.well-known/schemas/mcp-tool/v1` endpoint retrieves the JSON Schema for MCP tool definitions. You can use the schema for IDE autocompletion and validation.

.Example
[source,bash]
----
curl "http://localhost:8080/.well-known/schemas/mcp-tool/v1"
----
