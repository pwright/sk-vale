= Agent visibility model

[role="_abstract"]
Agent Cards support three visibility levels, controlled by the `apicurio.agent.visibility` artifact label. When OIDC or basic authentication is enabled, `GET /.well-known/agents` and the AI Catalog and ARD endpoints described in xref:getting-started/assembly-ai-catalog-ard.adoc[AI Catalog and ARD discovery] enforce visibility.

.Agent visibility levels
[cols="1,3",options="header"]
|===
|Visibility |Behavior

|`public`
|Visible to everyone, including unauthenticated clients

|`entitled`
|Visible to any authenticated user (this is the default)

|`private`
|Visible only to the artifact owner and registry administrators
|===

.Visibility label example
[source,bash]
----
curl -X PUT "http://localhost:8080/apis/registry/v3/groups/my-agents/artifacts/my-agent" \
  -H "Content-Type: application/json" \
  -d '{"labels": {"apicurio.agent.visibility": "public"}}'
----

*How entitlements work:* {registry} maps the A2A community entitlement concept to its existing RBAC model:

* *Groups* act as organizational namespaces
* *Entitling a client* = granting read access to the group containing the Agent Card artifacts
* *Client authentication* happens in an external identity provider, such as {keycloak} or another OIDC provider
* No new authorization primitives are required

.Discovery and entitlement configuration properties
[cols="2,1,3",options="header"]
|===
|Property |Default |Description

|`apicurio.a2a.default-visibility`
|`entitled`
|Default visibility for new Agent Card artifacts (`public`, `entitled`, or `private`)
|===

Visibility labels control which Agent Cards appear in `/.well-known/agents` search results and in the AI Catalog and ARD responses. When you retrieve a card by ID through `/.well-known/agents/\{groupId}/\{artifactId}` or the core REST API, only read authorization applies. {registry} does not check the visibility label.

NOTE: When neither OIDC nor basic authentication is configured, {registry} skips visibility filtering and all agents are visible to all users.
